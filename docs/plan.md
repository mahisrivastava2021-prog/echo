# Echo: MVP Build Plan

## Context
Echo is a multilingual, mobile-first web app that helps migrant domestic workers (FDWs) in Singapore understand their rights under MOM rules. It triages how serious a situation is, keeps a private encrypted journal, and connects workers to help. It started as a Create4good 2026 visual prototype. The goal now is a **working demo**: a public GitHub repo plus a live GitHub Pages site, used as a portfolio piece for AI/SWE internships. Hosting must cost $0. Privacy and safety drive every design choice. The demo must work fully without any backend.

**Decisions from your answers:** English + **Bahasa Indonesia**. No native-speaker reviewer, so we machine-translate, back-translate and flag it honestly. Live LLM mode is a **stretch goal** using **Gemini (free tier)**. Stack is **React + TypeScript**.

**Current state:** `echo/` is empty. git and `gh` are installed. **Node.js is not installed**, so the first step is `brew install node`.

## 1. Architecture & stack

```
 Browser (GitHub Pages, static PWA). Everything below runs on-device.
 ┌───────────────────────────────────────────────────────────────┐
 │ UI (React)  ── Exit button (always visible) ── Emergency btn  │
 │   │                                                           │
 │   ▼ message (text / Web Speech)                               │
 │ [1] Crisis rules (keywords + tiny classifier). Runs FIRST.    │──► crisis ⇒ Emergency screen
 │ [2] Retrieval: BM25 over static KB index (kb/*.json)          │
 │ [3] Answer source:                                            │
 │      • Demo mode: scripted conversation / retrieved rule cards│
 │      • Live mode: POST to Worker ──(fail/timeout)──► demo     │
 │ [4] Severity = max(rules, model). The model can only escalate.│
 │ [5] Journal: AES-GCM encrypted in IndexedDB, key from PIN     │
 └───────────────────────────────────────────────────────────────┘
          │ live mode only (opt-in, stretch)
          ▼
 Cloudflare Worker (free): CORS lock, rate limit, daily cap, no logging
   → Gemini embeddings (query) + dense retrieval over precomputed vectors
   → Gemini Flash, JSON schema output → validated → client
```

| Choice | Why |
|---|---|
| **Vite + React + TypeScript** | Fast static build, the most interview-recognisable stack, and types catch bugs in safety-critical logic. |
| **vite-plugin-pwa** | Offline support and installability for free. The app shell and KB are cached, so the demo works offline. |
| **Plain CSS modules (no UI library)** | Small bundle and nothing to explain beyond CSS. Mobile-first from the start. |
| **State-based screens (no router) or HashRouter** | GitHub Pages has no SPA fallback, and the exit flow must not leave history entries. |
| **MiniSearch (BM25) client-side retrieval** | Works with zero backend in demo mode and runs per-language indexes. It's deterministic and testable. |
| **Precomputed Gemini embeddings (static JSON)** | Used for dense/cross-lingual retrieval in live mode. They're generated by a build script, so there's no runtime cost to embed the KB. |
| **Gemini Flash via Cloudflare Worker** | $0 on the free tier, no key in the browser, and structured JSON output. |
| **zod** | One schema validates LLM output and demo scripts. Bad output falls back to a safe default. |
| **idb + WebCrypto** | Native encryption with no crypto library to trust. |
| **jsPDF (lazy-loaded)** | Client-side PDF, so journal content never leaves the device. |
| **Vitest + Playwright, GitHub Actions** | Unit tests and evals run in CI. Deploys to Pages on every push to `main`. |

**Voice (Web Speech API) limitations, shown to the user and noted in the README:**
- Works in Chrome/Edge (desktop and Android) and Safari (iOS/macOS). **Firefox doesn't support it.**
- `en-SG`/`en-US` and `id-ID` are supported. Accuracy drops with accents, code-switching (Indonesian + English) and background noise.
- **Privacy:** Chrome sends audio to Google's servers for recognition, so it isn't on-device. Voice is therefore opt-in, with a one-line disclosure. Typing is always available. A future option is on-device Whisper (transformers.js), which is too heavy for the MVP.

## 4. Knowledge base, citations & evals

**Sources (official only; record the URL and access date for each):**
- MOM pages on FDW employment: rest days and compensation-in-lieu, salary payment (monthly, within 7 days, salary records), the standard employment contract, medical care and insurance, safe working conditions and accommodation, upkeep (food), and the employer's obligations under the Employment of Foreign Manpower Act and the Work Permit conditions for FDWs.
- How to get help: the MOM FDW helpline and channels, CDE, and HOME. We cite these but don't copy third-party content wholesale.

**Chunking:** I write the chunks by hand rather than splitting pages automatically, because the KB is small and accuracy matters most.
- One chunk is **one rule or one process**, about 80–200 words.
- Frontmatter holds `id` (e.g. `rest-day-01`), `title`, `source_url`, `accessed`, `topic`, `lang`.
- The chunk text is a plain-language paraphrase plus a short quote of the key official wording.
- Indonesian versions are machine-translated, back-translated to English, diff-checked, and tagged `reviewed: false`.

**Citations:** every answer carries `citations: [chunkId]`. The UI shows the title, a source link and the date accessed. Tests assert:
- every chunk ID cited in demo scripts exists;
- every chunk has a URL;
- live-mode answers only cite chunk IDs that were given to the model. Anything else is rejected, and the app falls back to the rule cards.

**Eval set (50 per language, 100 total)** in `evals/scenarios.<lang>.jsonl`. Each line has `{id, text, expected_severity, expected_chunks, tags}`.
- Mix: ~10 mild, ~13 moderate, ~13 serious, ~14 crisis.
- Hard cases:
  - indirect crisis language ("I can't take it anymore", "she locks me in");
  - negations and false-positive traps ("killing time", "my employer said she'd kill me if I told", which *is* crisis);
  - typos, code-switching, and short or voice-transcript-style text.
- The ID set is written natively (with LLM help) and not just translated from EN, plus back-translation checks.
- The classifier trains on a **separate** synthetic set, never the eval set, to avoid leakage.

**Metrics (in `evals/results/`, shown in the README):**
- **Crisis recall = 100% (CI gate)**;
- crisis precision;
- 4-class triage accuracy and confusion matrix;
- retrieval recall@3 vs `expected_chunks`;
- live mode only: citation validity rate and schema-valid rate.

**Severity definitions** (documented in an ADR):
- **mild**: an information question;
- **moderate**: a contract breach such as late salary or a missed rest day;
- **serious**: sustained breaches or harm, such as months unpaid, passport kept, insufficient food, repeated verbal abuse or threats;
- **crisis**: physical or sexual violence, self-harm or suicidal intent, confinement, or immediate danger.

## 5. Risks & mitigations

| Risk | Mitigation |
|---|---|
| **Wrong legal info** | Answers come only from cited KB chunks. Every chunk links to an official MOM page and shows its access date. The "information, not legal advice" disclaimer is on every answer. Demo scripts are hand-checked against sources. Live mode is limited to the retrieved chunks, and its citations are validated. |
| **Missed crisis** | Deterministic rules run first, client-side, in plain code with no network. The final severity is the max of the rules and the model. CI gate requires 100% crisis recall. Keywords lean toward recall. The emergency button is always one tap away on every screen. |
| **Privacy leaks** | Demo mode makes **zero network requests**, which a Playwright test asserts. No analytics, cookies or CDNs, plus a CSP meta tag. The journal is encrypted with AES-GCM using a key from PBKDF2 (600k iterations, random salt). The key lives only in memory, and the app auto-locks on exit or when backgrounded. Chat isn't persisted unless saved to the journal. The exit button wipes in-memory chat, locks the journal, and uses `history.replaceState` so the back button can't return. Voice and live mode are opt-in with disclosures. **Gemini's free tier may use prompts for training, so live mode warns "do not enter real personal details" (demo only).** |
| **Weak PIN** | A 4–6 digit PIN can be brute-forced offline if the device is seized. This is documented honestly. A future version could use a longer passphrase or WebAuthn. |
| **Translation quality** | Back-translation checks, an `unreviewed` flag in the UI footer and README, ID crisis keywords that include informal variants, and a separate ID eval set. |
| **API costs / abuse** | The free tier has no billing account, so the cost is $0 by construction. The Worker also has a per-IP rate limit, a global daily cap below the free quota, CORS locked to the Pages origin, and the key stored as a Worker secret. Any failure falls back to demo mode. |
| **Outdated emergency numbers** | Each contact lists its source URL and `verifiedOn` date. **Numbers I can't verify on the official site are marked "unverified" and not shown as one-tap call buttons.** |

**Emergency contacts (verified in M1, not from memory):**
- 999 (police);
- 995 (ambulance);
- the HOME helpline (from home.org.sg);
- the CDE helpline (from cde.org.sg);
- the MOM FDW helpline (from mom.gov.sg). This is worth adding as well.

## 7. Final demo flow (~3 min)
1. **(0:00)** Open the live link on a phone or in a mobile-view browser. Point out the demo banner and the exit and SOS buttons.
2. **(0:20)** Tap the example "My employer hasn't paid me for 2 months". Echo gives an empathetic reply and a **Serious** badge. It cites the MOM salary rule (tap it to show the source) and explains the next steps for filing with MOM.
3. **(0:50)** Tap "Save to journal" and set a PIN. Show the dated entry, then export it as a PDF.
4. **(1:20)** Switch to Bahasa Indonesia. Use the mic or the example "Saya tidak dapat hari libur" (no rest day) to get a **Moderate** badge with the rest-day citation in Indonesian.
5. **(1:50)** Type a crisis message. The **emergency screen opens instantly**, before any AI runs. Show the one-tap call buttons and their sources.
6. **(2:20)** Tap **Exit**. A neutral decoy screen appears and the back button doesn't return. Show how to get back in, and that the journal is locked again.
7. **(2:40)** In the README, show the eval table (100% crisis recall) and the architecture diagram.

## 8. GitHub walkthrough (done step by step at M0)
1. `brew install node` and then `node -v`.
2. `gh auth login`: log in through the browser, choosing GitHub.com, HTTPS, and log in with web browser.
3. Set your git identity: `git config --global user.name` / `user.email`. You can use GitHub's no-reply email to keep your address private.
4. Scaffold the app in `echo/`, then run `git init`, `git add`, and a first commit. I'll explain staging vs committing.
5. `gh repo create echo --public --source=. --push`
6. Add `.github/workflows/deploy.yml`. In the repo, go to **Settings → Pages → Source: GitHub Actions**. Push, watch the Actions tab, then open `https://<username>.github.io/echo/` (Vite `base: '/echo/'`).

## 9. Verification (each milestone)
- `npm run test` covers unit tests: crypto round-trip, crisis rules, retrieval, demo-script citation integrity.
- `npm run eval` checks crisis recall = 100% and prints the triage metrics. It runs in CI.
- `npm run e2e` runs Playwright on a mobile viewport. It covers the demo flow, the exit button and back-navigation, **asserts no external network requests in demo mode**, and checks that a crisis message opens the emergency screen even if the Worker URL is unreachable.
- Manual check on a real phone (Android Chrome and iOS Safari) after each deploy.
